# MAX Chat (тестовое задание)

Веб-чат для мессенджера MAX на базе [GREEN-API](https://green-api.com/max). Можно войти по данным инстанса, начать чат по номеру телефона, отправлять и получать текстовые сообщения. Внешний вид минимально повторяет [web.max.ru](https://web.max.ru/).

## Возможности

- **Чаты не пропадают после перезагрузки.** Список чатов и последние 100 сообщений каждого хранятся в `localStorage` отдельно для каждого инстанса. При открытии чата его история подтягивается из `GetChatHistory`, так что видны и сообщения, отправленные с телефона. Кэш показывается сразу, серверная история подмешивается следом.
- **Маска номера** `+7 999 123-45-67` и `+375 29 123-45-67`. Можно вставить номер в любом виде, например `8 (999) 123-45-67`. Разделители стираются как обычные символы. `CheckAccount` в MAX принимает только номера России и Беларуси, поэтому другие коды отклоняются ещё до запроса.
- **Оптимистичная отправка.** Сообщение появляется сразу со статусом «отправляется», потом становится «отправлено» или «не отправлено». Неотправленное можно отправить повторно кнопкой «Повторить».
- **Лимит длины** в 20 000 символов, как в `SendMessage`. Счётчик появляется, когда до лимита остаётся 10 %.
- **Разделители по дням** в переписке («Сегодня», «Вчера», «28 сентября»). В списке чатов у сообщений за сегодня показывается время, у более старых — дата.
- **Адаптив**, контрольные точки 576 / 768 / 1440 px. На телефоне виден один экран: список или открытый чат, из чата можно вернуться кнопкой «назад». С 768 px экран делится на две колонки, с 1440 px сайдбар становится шире.
- **Мелочи ввода.** Enter отправляет, Shift+Enter переносит строку. После отправки фокус остаётся в поле, поэтому клавиатура на телефоне не закрывается. У полей есть `name` и `autocomplete`, и менеджер паролей подставляет данные инстанса.

## Запуск

Нужен Node.js 22+.

```bash
npm ci
npm run dev        # http://localhost:5173
```

| Скрипт              | Что делает                                   |
| ------------------- | -------------------------------------------- |
| `npm run dev`       | dev-сервер                                   |
| `npm run build`     | проверка типов и production-сборка в `dist/` |
| `npm run preview`   | раздача собранного `dist/`                   |
| `npm run lint`      | oxlint, в том числе проверка границ слоёв    |
| `npm run typecheck` | `tsc -b`                                     |

Бэкенд не нужен: GREEN-API отдаёт CORS-заголовки, и браузер обращается к нему напрямую.

### Подготовка инстанса

1. В [личном кабинете GREEN-API](https://console.green-api.com/) создайте инстанс MAX и авторизуйте его.
2. В настройках инстанса включите **Receive webhooks on incoming messages and files**. Поле `webhookUrl` оставьте **пустым**: если в нём задан URL, уведомления уходят туда и `ReceiveNotification` их не получает. Новые настройки начинают действовать в течение нескольких минут.
3. Откройте приложение, введите `idInstance` и `apiTokenInstance`, создайте чат по номеру и напишите сообщение. Ответ собеседника появится в том же чате.

## Стек

- **React 19 + TypeScript** (strict, `noUncheckedIndexedAccess`).
- **Vite 8** — сборка и dev-сервер. Алиас `@/` берётся из `tsconfig` через встроенный `resolve.tsconfigPaths`.
- **SCSS Modules** (`sass-embedded`) поверх CSS custom properties, **clsx** для составных классов.
- **Vitest** — тесты, **oxlint** — линтер, **Prettier** — форматирование.

Что сознательно не взято:

- роутер — экранов два, и какой из них показать, зависит только от наличия сессии;
- стейт-менеджер и TanStack Query — всё состояние сводится к списку чатов, и `useSyncExternalStore` поверх репозитория с ним справляется;
- axios — хватает `fetch`;
- библиотека виртуализации — не нужна, т.к лимит 100 сообщений выставлен.

## Ограничения

- Токен хранится в `localStorage` открытым текстом. Для демо это приемлемо, в продакшене так бы не делал.
- Очередь уведомлений у инстанса одна, поэтому две открытые вкладки делят входящие сообщения между собой.
- `CheckAccount` ограничен по частоте. На бесплатном тарифе GREEN-API действует лимит собеседников в месяц. При превышении приложение показывает понятную ошибку.
- Уведомления хранятся в очереди GREEN-API 24 часа. Более старые входящие не придут через polling, но попадут в чат через `GetChatHistory`.
- В журнал `GetChatHistory` сообщения попадают с задержкой до пары минут.
